五分鐘交接 Demo 腳本

  1. 開 /dashboard說明這是使用者主要工作台。正常會看到摘要區、分析對話輸入框與資料觀察區。
  2. 問單月查詢輸入：2025-03 各事業群營收。觀察回答是否能列出 2025-03 的事業群營收表格。
  3. 問兩期間比較輸入：比較 2025-02 和 2025-03 各事業群營收變化。這題適合說明系統會走固定規則、可重現的 deterministic 流程，取得兩個月份可比較資料。
  4. 開 Tool 工具箱開 /handoff/tools.html。如果 Dashboard 沒有顯示 trace 或 tool 區塊，就從工具箱說明這題會用到哪種工具。
  5. 搜尋 Tool在工具箱搜尋：get_entity_period_pair_table。說明它適合支援兩期間、依 entity 分組的比較表。
  6. 展示安全拒絕回 Dashboard 問：預測下個月營收會不會改善。正常情況會說明目前不支援預測，而不是硬湊答案。
  7. 開健康檢查開 /api/health。若 status 是 warning，請看下一段說明，不要只用顏色判斷系統壞掉。

正式啟動方式

Backend

USE_LLM_PLANNER=true uv run python demo_web.py

若展示希望讓 LLM Planner 保持開啟，啟動後端時要帶 USE_LLM_PLANNER=true。一般 deterministic Demo 不依賴 LLM Planner，但開著可以展示 Agentic planning 路徑。

Frontend

cd frontend
npm run dev -- --hostname 0.0.0.0 --port 3000

Handoff site 由 frontend/public/handoff/ 提供，不需要另一個 handoff server。

入口URL用途
Dashboard/dashboard現場 Demo 與一般問答。
Handoff/handoff/新人交接教材。
Backend health/api/health確認 API、pipeline 與 planner 狀態。

health warning 怎麼看

目前 /api/health 可以是 HTTP 200，但 status=warning。這代表服務有回應、pipeline 已載入，但資料品質檢查提醒維護者要注意解讀限制。

  • warning 原因：目前 /api/pipeline-status 回報兩個資料對齊提醒：「有新事業群只出現在庫存：未對應」，以及存在 revenue-only / inventory-only rows。
  • 對 deterministic Demo 的影響：不影響本次交接展示中的單月營收、兩期間比較與預測安全拒絕。
  • 對 LLM Planner 的影響：LLM Planner 可以開啟並回答，但回答仍要遵守證據檢查與限制描述。
  • 對 Proactive 的影響：可以產生草稿，但發布前應特別看資料品質 warning；主動草稿仍需人工核准。

Windows PowerShell 常用命令

netstat -ano | findstr :3000
Get-Process -Id <PID> | Select-Object Id,ProcessName,StartTime,Path
Stop-Process -Id <PID>
$env:USE_LLM_PLANNER="true"
uv run python demo_web.py

Server / Linux 常用命令

ss -ltnp | grep -E ":(3000|8765)"
ps -eo pid,ppid,etime,cmd | grep -E "demo_web|next dev"
tmux new -s revenue-poc
# backend
USE_LLM_PLANNER=true uv run python demo_web.py
# frontend
cd frontend && npm run dev -- --hostname 0.0.0.0 --port 3000
tail -f /tmp/rvn_frontend.log

停止服務前先確認 PID、啟動時間與命令內容；不要直接對不明 process 使用強制停止。

常見故障排除

port already in use

用 ss -ltnp 或 PowerShell netstat -ano 找 PID，再確認 process start time。只停止自己啟動的服務。

Frontend 連不到 Backend

檢查 PYTHON_API_BASE、/api/health、backend port 8765 是否在聽。

原始碼已改但頁面仍是舊版

重新執行 generator，必要時重啟 Next dev server；build 後若 chunk 不一致，也要重啟 frontend。

缺少資料檔案

看 config.py 與 health response 的 data path / warning。不要在 handoff site 放真實資料。

Tool 沒出現在 Registry

確認 tool_registry.py 有 ToolContract，且測試更新。

MCP Tool 沒出現

確認 ToolContract 允許 MCP exposure，並與 mcp_server/server.py registration 一致。

semantic validation fail

通常是 metric、dimension 或 task evidence 定義不一致；先查 Semantic Layer 定義檔。

evaluation run 找不到

確認 evaluation output path 與 generated artifacts。artifact 是驗收結果，不是 production source。

static handoff 某頁 404

確認檔案在 frontend/public/handoff/，內部連結使用 .html 或 /handoff/。

CSS / JS 路徑錯誤

所有資源應使用相對路徑 assets/...；不要使用 file scheme、外部 CDN 或 localhost 靜態資源。

本網站由 repository source code、設定、測試與 evaluation datasets 產生；不包含真實營收或庫存數字。
