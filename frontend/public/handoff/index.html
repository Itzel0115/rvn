交接開始

使用者可以直接用中文詢問營收與庫存問題。Agent 會判斷問題、選擇受控分析工具、檢查證據是否足夠，再產生回答、表格與圖表。資料不足時，系統會嘗試合法的補充分析，或清楚說明目前無法完整回答。

第一次接觸系統先理解它能做什麼、資料怎麼進來、哪些邊界不能越過。 我要現場展示照五分鐘 Demo 腳本開 Dashboard、問問題、看 Tool 與 health。 我要接手修改從新增 Tool、KPI、問題類型三個配方開始。

10 分鐘最短閱讀路徑

  1. 系統總覽知道支援能力與刻意不做的事。
  2. 一題怎麼跑看懂一個問題如何變成工具執行與受限回答。
  3. Tool 工具箱查完整 ToolContract、參數、evidence 與測試。
  4. 展示與操作照腳本實際啟動與展示。

系統核心原則

Agent 負責規劃

Agent 判斷現在該查什麼，不直接任意計算或讀檔。

Tool 負責計算

營收、庫存、趨勢、排名與圖表由 deterministic tools 執行。

Registry 是邊界

每個工具的 args、KPI、task family、evidence type 與 MCP exposure 都在 ToolContract 中定義。

證據不足不硬湊

Evidence Validator 會要求 primary evidence；合法補證失敗時回 partial 或 capability gap。

主動洞察需人工核准

Proactive draft 只有經 approval 與 publication gate 才能發布 artifact。
